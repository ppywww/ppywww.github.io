## 1. 产品定位

### 1.1 一句话描述

> **一个中文个人综合博客：记录技术学习、生活观察与读书所得，以"读得舒服"为第一优先级。**

### 1.2 定位三角

- **内容**：技术长文 + 生活随笔 + 读书笔记，三线并行，不追求日更，追求**可回看**
- **读者**：未来的自己（第一读者）+ 同行与朋友
- **气质**：克制、干净、可信。**不炫技，但处处有细节**

### 1.3 与参考站（Lil'Log）的关系

**借鉴**：信息架构、阅读宽度约束、双主题工程实现、零 Web Font 性能策略、客户端搜索、SEO 完整度。
**拉开差距**：内容更综合（不只是技术），视觉更有个人识别度（Lil'Log 的 PaperMod 是"无风格风格"）。

## 2. 目标与非目标

### 2.1 目标（本版本必须达成）

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 打开即读，无等待感 | 首屏 LCP < 1.5s（4G），Lighthouse Performance ≥ 95 |
| G2 | 长文阅读舒适 | 正文宽度 720±40px，行高 ≥1.7，中文字号 ≥16px |
| G3 | 找得到东西 | 站内搜索可搜标题+正文+标签；归档/标签/分类三路可达 |
| G4 | 想订阅的人能订阅 | RSS 可用，且一次性订阅全站 |
| G5 | 老板自己能发文章 | 写 Markdown → 提交 → 自动构建上线，**不超过 3 步** |
| G6 | 站得住场面 | 视觉不输参考站；深色模式无闪烁 |

### 2.2 非目标（明确不做，防止范围蔓延）

- ❌ 用户注册 / 登录 / 后台管理系统（静态站，作者即唯一编辑）
- ❌ 服务端数据库、服务端渲染（SSR）
- ❌ 付费内容 / 会员体系
- ❌ 移动 App / 小程序
- ❌ 多语言（中文为主，i18n 仅预留结构不实现）
- ❌ 自建评论后端（用 Giscus，基于 GitHub Discussions）
- ❌ 相册/图床系统（V2 再议）

## 4. 核心用户旅程

### J1 · 首次访问（陌生人）
落地首页 → 看到"人 + 一句话" → 扫一眼最新文章 → 点进一篇 → 读完 → 看到相关文章/标签 → 订阅 RSS 或收藏。

**关键设计**：首页前 1 屏必须同时回答"这是谁"和"这里有什么"。

### J2 · 定向查找（老读者）
搜索框（Alt+/）→ 输入关键词 → 即时结果 → 直达文章。

### J3 · 主题式阅读
标签页 → 选一个标签 → 该标签下全部文章（按时间倒序）→ 连续阅读。

### J4 · 老板发布（关键内部旅程）
本地写 `content/posts/2026-09-30-xxx.md` → `git commit && git push` → CI 自动构建 → 上线。
**必须 ≤ 3 步**，且失败时能在 GitHub Actions 日志里一眼看出原因。

## 6. 内容模型

### 6.1 内容类型

| 类型 | 目录 | 说明 |
|---|---|---|
| **Post** | `content/posts/` | 文章，有分类/标签/系列 |
| **Page** | `content/pages/` | 独立页（关于我） |
| **Project** | `content/works/` | 作品条目（结构化字段） |

### 6.2 Post Front-Matter 契约（**冻结项**）

`@yaml
---
title: "文章标题"              # 必填
date: 2026-09-30T14:00:00+08:00 # 必填，带时区
lastmod: 2026-10-02T09:00:00+08:00 # 选填，有则显示"更新于"
draft: false                   # 必填
description: "一句话摘要，用于列表卡片与 SEO"  # 必填
categories: ["技术"]           # 必填，仅限 4 个栏目之一
tags: ["Hugo", "性能优化"]      # 选填，自由
series: "从0搭建个人博客"        # 选填，系列名
cover: "/images/cover/xxx.webp" # 选填，列表缩略图
toc: true                      # 选填，默认 true
comments: false                # 选填，默认 false
math: false                    # 选填，按需加载 KaTeX
---
`@

**约束**：`categories` 只允许 `技术 / 生活 / 读书 / 作品` 四值，构建时应校验并报错。

### 6.3 文件命名规范

- 文章：`content/posts/YYYY-MM-DD-slug.md`（日期前缀保证排序稳定）
- 或使用 Page Bundle：`content/posts/YYYY-MM-DD-slug/index.md` + 同目录图片（推荐，图片与文章同生共死）
- Slug 用英文小写 + 连字符

### 6.4 分类 vs 标签

- **分类（Category）**：少而稳，4 个，一篇文章**有且仅有 1 个**主分类 → 承担栏目导航
- **标签（Tag）**：多而活，自由生长 → 承担主题聚类
- **系列（Series）**：可选，用于连载 → 文末自动列出同系列文章

## 7. 页面清单与规格

### 7.1 首页 `/` —— P0

| 区块 | 规格 |
|---|---|
| 个人卡片 | 头像 + 昵称 + 一句话自我介绍 + 社交图标（GitHub / RSS / 邮箱） |
| 最新文章 | 卡片流，每页 10 篇；卡片 = 标题 + 摘要（2 行截断）+ 日期 + 阅读时长 + 分类 + 标签 |
| 分页 | 上一页 / 下一页 + 页码 |

### 7.2 文章详情 `/posts/<slug>/` —— P0

`@
面包屑：首页 / 分类 / 文章标题
H1 标题
元信息行：2026-09-30 · 8 分钟 · 技术 · 标签1 标签2
[可选] 封面图
TOC（默认折叠，Alt+C 展开；<details> 实现）
正文（720px）
  - h2/h3 自动锚点
  - 代码块：语言标签 + 复制按钮 + 行号（可选）
  - 行内代码、引用、表格、图片（灯箱）
  - 数学公式（math: true 时才加载 KaTeX）
文末：更新于 / 版权声明（CC BY-NC-SA）
系列导航（若有 series）：上一篇 / 下一篇
相关文章（同分类或同标签，最多 3 篇）
评论区（Giscus，默认关闭）
`@

### 7.3 归档 `/archives/` —— P0
按 年 → 月 两级分组，标题带计数上标；条目「日期 + 标题 + 阅读时长」，整行可点。

### 7.4 分类 `/categories/` 与 标签 `/tags/` —— P0
总览页：条目 + 计数。详情页：该分类/标签下文章列表（倒序）+ 描述。

### 7.5 搜索 `/search/` —— P0
输入框（自动聚焦，`Alt+/` 唤起）→ 即时结果（标题 + 高亮摘要 + 日期）。空态显示"输入关键词开始搜索"。无结果为友好空态。

### 7.6 作品 `/works/` —— P0（MVP 内）
卡片网格，每项：缩略图 / 名称 / 一句话 / 技术栈标签 / 链接（GitHub / Demo）。

### 7.7 关于 `/about/` —— P0
长文页，可含时间线（经历）、技能、联系方式、本站技术栈说明。

### 7.8 404 —— P0
友好提示 + 返回首页 + 搜索框 + 最新 3 篇文章。

## 9. 交互与状态细节

| 场景 | 要求 |

| 主题切换 | 首帧前生效（内联脚本），切换瞬时无过渡闪烁；记忆到 localStorage |

## 11. 内容运营规范

- **写作格式**：Markdown（GFM）；标题层级从 `##` 开始（H1 留给标题）
- **摘要**：每篇必写 `description`，40–80 字，用于列表与 SEO
- **图片**：优先 `.webp`，宽度 ≤ 1600px，放在文章 Page Bundle 内
- **更新**：修改旧文时同步 `lastmod`，页面显示"更新于"
- **密级**：`draft: true` 不上线
- **节奏建议**：每月 2–4 篇，技术 2 : 生活 1 : 读书 1（不构成 KPI）

## 12. 品牌方向

### 12.1 站点名称（D1 待拍板）

| 候选 | 气质 | 备注 |
|---|---|---|
| **A. 拾光集 / Notes** | 温和、有生活感 | 偏向综合博客气质 |
| **B. 半山笔记** | 沉稳、有留白感 | 中文感强，易记 |
| **C. 待你指定** | — | 你若已有想法，直接给我 |

> 站名会出现在：导航 Logo、页脚版权、RSS 标题、OG 卡片、404 页。**越早定越好，但后期可全局替换**（单点配置）。

### 12.2 视觉方向（D3 待定）

**方向一 · 纸感留白**（推荐）：米白底 + 深墨字 + 一个低饱和点缀色（墨绿/赭石）；衬线标题 + 无衬线正文；大量留白。气质接近"电子杂志"。
**方向二 · 极简冷调**：白/近黑双主题 + 单一强调色（靛蓝）；全无衬线；信息密度略高。最接近参考站。
**方向三 · 暖色个人化**：奶油底 + 暖橙点缀 + 圆角卡片 + 手写体标题。更有"人"的味道，但容易显得不专业。

→ 由 `docs/research/visual-references.md`（视觉调研）回来后统一定稿。

## 15. 风险与依赖

| 风险 | 影响 | 应对 |
